# 验收与降级

## DOM 约定

每页使用 `section.slide` 和唯一、稳定的 `id`。目录使用 `<button data-goto="page-id">`，不使用会随插页失效的数字索引。补充详情使用 `<button class="zoomable" data-extra="纯文本详情">`，脚本按文本显示，不能把输入当 HTML 执行。一个页面内的链接、按钮与可编辑控件各自处理操作；点击正文不触发翻页。

底座的脚本集中在文件结尾。新增页面沿用 DOM 约定，保留 `#deck`、`#page-status`、`#prev`、`#next`、`#detail-dialog` 及其子控件。关闭详情只用关闭按钮、Esc 或遮罩，点击详情内容不关闭。键盘焦点在弹窗内，并在关闭后返回原控件。

## 自动检查

如本机有 Node.js 和 Playwright，从安装了 Playwright 的目录运行：

```sh
node /path/to/skill/scripts/check-deck.cjs /absolute/path/to/deck.html /absolute/path/to/qa-output
```

脚本也支持通过 `NODE_PATH` 指向已有模块目录。若缺浏览器，按当前环境允许的方式安装 Playwright Chromium，或使用可用浏览器工具完成相同检查。不要把没有执行的检查记录为通过。

脚本检查页面 ID、断链目录、页码、边界导航、弹窗开关、窄屏横向溢出、桌面内容溢出、离线外部依赖、打印显示与控制台错误，并保存逐页截图。自动检查只覆盖运行约定，不能证明叙事、内容真实或视觉美观。

## 人工检查

逐页查看截图，核对标题完整、图片无错误裁切、文字无遮挡、图表不失真、来源能读。至少在桌面和窄屏检查一次。更换语言、字体、图片或大幅增加内容后重新检查受影响页面。

有图片时等待加载完成并检查失败项。打印预览检查所有页、长页分页及补充详情；需要交付 PDF 时实际生成并逐页查看 PDF，不能只依赖打印 CSS 检查。

## 完成条件

1. 请求的内容和格式已交付，样张主题与模拟数据已替换或明确保留为示例。
2. 导航、目录、详情、键盘操作正常，无丢失页面或不可返回的弹窗。
3. 桌面无正文溢出，窄屏可阅读全部正文；没有加载失败的必要素材。
4. 已核对来源和数据；剩余缺口明确列出。
5. 报告实际测试环境、检查结果和未验证项。

无法使用浏览器时仍可完成结构检查和交付，但应标记“浏览器交互与视觉未验证”，不声称已通过完整验收。字体缺失使用系统回退；网络不可用仍能阅读本地稿。两轮修复后仍未解决的问题直接列出具体页面和影响，保留可用版本，避免无限返工。
